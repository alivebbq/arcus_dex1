# Arcus 自动交易面板

多账户永续合约交易工作台，包含趋势交易、网格交易和预留模块。服务器独立运行 `arcus-grid.service`，监听 `127.0.0.1:8787`，由 Caddy 提供 HTTPS。实际部署网址、钱包地址和凭证文件路径仅保存在被 Git 忽略的 `deployment.local.json`；登录信息保存在被忽略的 `deployment-access.txt`。

## 当前范围

- 多账户：输入名称、主钱包地址、API Key、API Signing Key、子账户编号，校验注册关系与密钥配对，展示余额、持仓、挂单。
- 账户区分：同钱包的不同子账户可分别添加，策略、成交统计和运行日志关联独立账户 ID；切换账号后同步切换相关数据。重复添加同钱包同子账户会被拒绝。
- 模块一：参考 `quant` 服务器正在执行的 ETH 1h SuperTrend，管理 ETH-USD 永续合约，提供真实信号、计划风险、模拟与实盘策略。
- 模块二：永续合约等差网格，做多或做空，真实行情模拟与实盘两种模式。设置区间、格数、投入保证金、合约杠杆和全仓/逐仓模式。创建后是草稿，点击启动才运行。
- 模块三：待定。

网格实盘订单使用 Arcus `ALO`（post-only），平仓网格使用 `reduceOnly`。新网格策略的投入金额是保证金预算，含 5% 面板缓冲预留；名义额度上限是保证金预算 × 所选杠杆。挂单数量同时受名义额度、全部开仓档位在区间上限或当前标记价格下的初始保证金要求约束，因此实际名义金额可能低于上限。非交易时段按提高的初始保证金率计算。此预算为面板的策略分配额度，逐仓设置不会把整个预算自动转入逐仓池；全仓模式的实际风险与其他仓位共用保证金。

实盘启动前先设置并核实 Arcus 合约杠杆及保证金模式。交易所仅返回 ACK 或请求超时时，不推断设置成功，也不重复设置；后台只读取 `/v1/leverages` 等待确认。拒绝会显示错误，确认后再刷新余额、持仓和挂单，条件满足才允许网格订单。启动实盘策略前要求该市场没有已有仓位/挂单，同一账户同一市场仅允许一个策略。不同市场会预留各自尚未使用的保证金，已计入交易所可用余额的持仓保证金不重复预留。

版本升级保留旧策略的名义预算、订单数量和现有交易所设置，页面标记“旧配置”。要使用新的保证金预算及杠杆选择，需要创建新的策略，避免把旧订单无意放大。

## 账户统计与策略删除

当前账号显示交易所可读取历史的累计成交金额、已实现盈亏和交易手续费，覆盖该子账户的全部市场、手工交易和其他程序的真实成交；模拟策略不计入。成交金额是每笔实际数量绝对值 × 实际成交价的总和，开仓和平仓都计入。已实现盈亏使用成交账本 `closedPnl`，已扣普通交易手续费，不重复扣费，也不包含资金费。负手续费代表返佣；强平或缺失字段的盈亏口径无法核验时显示待核验，不以零代替。

统计通过独立后台任务分页、去重和持久缓存，不阻塞交易对账。历史尚未读完时不显示不完整的累计值，页面展示同步状态和统计截止时间。完成后每 60 秒刷新，超过 180 秒的记录标记过期；所有接口读取按账号及子账户独立执行。统计缓存与数据库均位于被 Git 忽略的私有数据目录。

草稿、暂停或停止的模拟策略可删除，并同时清除其虚拟持仓和订单。实盘策略仅在暂停或停止、已结清持仓且订单状态完成核验后可删除；无法确认的订单或仍在管理的止损会阻止删除。删除操作仅移除策略记录，不替代撤单或平仓。账户成交统计和带账户归属的历史日志保留。

## 趋势策略依据与执行

2026-10-12 只读核对了参考项目 `quant` 的运行参数和已安装源码 SHA-256。其活跃策略执行 ETHUSDC 的小时 SuperTrend，四个源文件均与参考项目一致。完整源码快照和运行记录只保留在本地、排除在公开仓库之外；`tests/fixtures/quant_supertrend_reference.py` 仅保留不含账户、部署或运行状态信息的纯指标计算，用固定 OHLC 序列逐根核对。Arcus 使用自己的已收盘小时行情和独立预热历史，因此不承诺与币安出现相同信号或收益。

规则：HA 收盘价为趋势带中心，Wilder ATR/ADX 周期 14，趋势带宽 4×ATR，ADX 严格大于 20 的新翻转才入场。初始止损 3.5×ATR；单笔计划风险为当前可用保证金的 3%，受面板分配额度限制。默认逐仓 5 倍，允许在 1–5 倍内选择。有效反向信号平仓，不立即反手；启动预热期间不追入历史信号，同向趋势持续也不补开仓。按上海日界计算本策略 15% 日亏损额度，使用自有成交、实际手续费/资金费及自有成本按标记价计算的浮盈亏；确认达到上限后停止新开仓并进入撤单核验和只减仓退出。未知或不完整账本阻止新开仓，手动恢复不清空当日额度。

开仓偏移 0.5 USD、普通退出偏移 1 USD，均使用 ALO；开仓 60 秒未成交先撤单。原策略的限价保护止损偏移 0.2 USD，Arcus 通过原生 position TPSL 的 LIMIT/GTT 托管全持仓初始止损，可能按 Taker 成交。确认部分开仓成交后先建立保护，再处理剩余开仓单。观察到止损触发后 10 秒开始撤单核验和余量 MARKET/IOC 只减仓兜底，普通退出 60 秒后进入余量兜底；市价兜底设价格界限，仍可能部分成交，按真实状态继续处理，不推测平仓。

Arcus 每个市场只允许一个持仓级 SL，且不支持普通修改该未触发 TPSL。为避免撤旧建新的无保护窗口，2R 后的成本保本在服务器收紧，保留原来的交易所初始止损。此保本、10 秒兜底均需要服务器在线；服务器离线时只剩已确认的初始限价止损，不能保证成交。趋势暂停/停止撤销开仓单并停止新开仓，已有持仓继续受止损、保本和兜底管理。一个账户的同一 ETH-USD 仓位不能与手工交易或网格混用；其他市场可以继续交易，但共用可用保证金。

趋势预估保留原执行器的 98% 可用资金约束，并在风险计算中计入已核对的费率及 0.03% 止损滑点预留；界面单独显示费用/滑点预留和 2% 资金缓冲。所有下单、止损、撤单和应急身份在请求前持久化，ACK 及超时需要读取交易所状态确认，不重复未知下单。

盘口读取失败会阻止新挂单，但不会抹去已同步的有效标记价。公开行情不可用时，应急退出可读取官方账户的最新持仓标记价；所有来源均无有效价格时保留已有保护单并报错，不用旧成交价推测退出价格。其他市场的保证金预留无法核实时，只暂停新开仓，已有趋势持仓仍继续保护对账。

## 运行与安全

FastAPI + SQLite + 独立持久网格状态机 + 原生浏览器页面，不依赖页面持续打开。每 5 秒轮询市场，每 15 秒刷新账户。订单的客户端 ID 在请求发送前保存；请求超时后先核对交易所订单状态，不推断成交或重复开仓。

API Signing Key 用 Fernet 加密入库；服务器主密钥与登录密码哈希放在仅 root 可读的 `/etc/arcus-grid.env`。SQLite 数据目录 `/var/lib/arcus-grid` 权限 0700。登录会话使用 HttpOnly/Secure/SameSite Strict Cookie，并校验请求来源。

网格暂停和停止撤销本面板的订单，不强制市价平仓。趋势暂停和停止保留持仓保护，风险条件触发时仍可执行只减仓兜底。已有仓位会显示为残余持仓。挂单被拒绝、行情中断、账户数据过期、订单状态不明时会记录日志并停止新开仓。挂单成交有排队与不成交的可能。毛收益与实际手续费、资金费分别显示，最终交易所结算以账户记录为准。

若整个服务器离线，交易所已经接收的挂单不会自动撤销，恢复后按持久记录对账；可在 Arcus 直接撤单。Arcus 的断线撤单开关可能撤销所选范围内其他交易程序或手工订单，当前版本不启用它。

## 部署与测试

复制 `deployment.example.json` 为 `deployment.local.json`，填写自己的 HTTPS 网址、钱包地址和本地凭证文件路径，再执行 `python scripts/deploy.py`。凭证不会写入命令行或提交到 Git。Caddy 模板使用示例域名，部署脚本按本地配置渲染。重新部署保留加密主密钥、登录密码与数据库。服务器服务配置在 `ops/`。

测试：`python -m pytest tests backend/test_arcus.py -q`。检查覆盖趋势指标源码一致性、信号因果与去重、3% 计划风险、止损/部分成交/重启恢复、净日风险与保护退出，以及合约保证金、签名、网格、登录保护。实盘 API 测试只读账户与市场，不提交实盘订单。初版页面已完成本地桌面与手机检查；合约与趋势界面已通过 JavaScript 语法与 DOM 验证，线上浏览器截图受此前自动审批限制未完成。

2026-10-12 版本 1.2.0：上述测试命令共 105 项通过。部署校验脚本 `scripts/verify_deployment.py` 比对服务端源码 SHA-256，并通过 HTTPS 检查认证、账户状态、趋势已收盘行情和只计算的模拟仓位预估。

2026-10-12 版本 1.3.0：148 项测试通过，增加子账户隔离、成交统计分页/缓存/未知口径、策略删除守门及日志归属验证。线上累计统计已与相同截止时间的真实成交账本只读比对；删除接口通过一次性模拟草稿验证，未对现有策略执行停止或删除操作。
